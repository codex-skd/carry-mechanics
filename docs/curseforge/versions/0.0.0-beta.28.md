<h2>v0.0.0-beta.28 — Fix Third Person Render and Dead Code Cleanup</h2>

<h3>Fix</h3>
<ul>
<li><strong>Third person render not showing</strong>: Rewrote <code>LivingEntityRendererMixin</code> to cache the entity during <code>extractRenderState</code> via a <code>@Unique</code> field. Previously it only rendered for <code>AvatarRenderState</code> (first person arms) and used <code>Minecraft.getInstance().player</code> — causing the carried block to never appear in third person view or on other players.</li>
<li><strong>Double rendering</strong>: Removed <code>CarryingItemRenderLayer</code> and <code>AvatarRendererMixin</code> which rendered through <code>RenderLayer</code>, conflicting with the mixin approach. The mixin now handles all rendering.</li>
<li><strong>Dead code removed</strong>: Deleted <code>ICarryOnRenderState</code>, <code>PlayerRenderStateMixin</code>, and <code>AvatarExtractorMixin</code> — all were only consumed by the removed render layer.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>LivingEntityRendererMixin</code>: Now uses <code>@Unique private Entity carryMechanics$currentEntity</code> cached during <code>extractRenderState(LivingEntity, LivingEntityRenderState, float)</code> to access the correct entity for each render call.</li>
<li><code>EntityRendererMixin</code>: Unchanged — continues to suppress name tags on carried entities.</li>
<li><code>mixins.json</code>: Cleaned up — removed <code>AvatarRendererMixin</code>, <code>AvatarExtractorMixin</code>, <code>PlayerRenderStateMixin</code>.</li>
<li><code>.github/workflows/</code>: Removed (GitHub Actions not used; CI is GitLab).</li>
<li>Logo: Added <code>carry_mechanics.png</code> and <code>assets/carry_mechanics/icon.png</code>, referenced in <code>neoforge.mods.toml</code>.</li>
<li><code>README.md</code>: Updated version badge to beta.27, added Requirements + Installation sections.</li>
</ul>
