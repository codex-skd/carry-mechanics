<h2>v0.0.0-beta.43 — Carried block now renders as a real held item</h2>

<h3>Fix</h3>
<ul>
<li><strong>Root cause of the broken block visuals:</strong> the carried block was rendered as a raw <code>BlockModelRenderState</code> via <code>BlockDisplayContext.create()</code>. In this Minecraft version that class carries no held-in-hand transform at all (no scale, rotation or offset), so the previous first/third-person positioning relied on hand-picked <code>translate</code>/<code>rotate</code> values that never matched the player's actual hand bone — hence invisible in first person and floating inside the body in third person.</li>
<li><strong>First person:</strong> the carried block is now resolved and rendered as an <code>ItemStack</code> of the block via <code>ItemModelResolver</code> with <code>ItemDisplayContext.FIRST_PERSON_RIGHT_HAND</code>, using the same base transform vanilla uses for a held item (<code>ItemInHandRenderer#applyItemArmTransform</code>). The display context already carries the correct scale/rotation, so no manual guesswork offsets are needed anymore.</li>
<li><strong>Third person:</strong> same item-based approach with <code>ItemDisplayContext.THIRD_PERSON_RIGHT_HAND</code>, anchored to the player model's hand bone via <code>PlayerModel#translateToHand</code> plus the same small offset vanilla's <code>ItemInHandLayer#submitArmWithItem</code> applies for a right-hand item — matching how every other held item is drawn, instead of a full-block-sized offset from the feet.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>CarriedBlockRenderer</code> — now resolves an <code>ItemStackRenderState</code> for <code>new ItemStack(blockState.getBlock().asItem())</code> via <code>ItemModelResolver.updateForLiving(...)</code> instead of a <code>BlockModelRenderState</code>.</li>
<li><code>ICarryOnRenderState</code> / <code>PlayerRenderStateMixin</code> — added a cached <code>ItemStackRenderState</code> on the avatar render state, resolved once per frame during <code>extractRenderState</code> (where the entity is available) and consumed during <code>submit</code>.</li>
<li><code>AvatarExtractorMixin</code> — resolves the carried block's item render state with <code>ItemDisplayContext.THIRD_PERSON_RIGHT_HAND</code>.</li>
<li><code>CarryingItemRenderLayer</code> — anchors to the hand bone and submits the resolved <code>ItemStackRenderState</code> instead of drawing a block model with manual offsets.</li>
<li><code>ItemInHandRendererMixin</code> — resolves and submits the item with <code>ItemDisplayContext.FIRST_PERSON_RIGHT_HAND</code>, using vanilla's own arm-transform offset instead of hand-picked rotation/scale values.</li>
</ul>
