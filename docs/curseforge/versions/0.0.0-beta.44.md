<h2>v0.0.0-beta.44 — Carried block held with both arms, matching Carry On's look</h2>

<h3>Fix</h3>
<ul>
<li><strong>Block no longer anchored to a single hand:</strong> the previous attempt anchored the carried block to the right hand bone, which still looked like holding an item in one hand instead of carrying it with both arms in front of the chest. Ported the actual positioning logic from the reference mod (Carry On): the block is now placed with a fixed transform relative to the player's torso — scaled down, pulled in front of the body and slightly down — so it looks embraced with both arms and stays stable at any camera angle instead of following arm-swing animation.</li>
<li><strong>First person now shows the block instead of your own hands:</strong> instead of drawing the block alongside the vanilla hand render, the mod now cancels the hand render entirely via NeoForge's <code>RenderHandEvent</code> while carrying a block and draws the carried block in its place — the same technique Carry On uses, giving the "both hands carrying it" look instead of one hand awkwardly holding it.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>CarryRenderHelper</code> (new) — ported torso-relative transform math (scale/translate/rotate) from Carry On's positioning code, adapted to this mod's <code>CarryData</code>/<code>ModelOverrideHandler</code>.</li>
<li><code>CarriedObjectRender</code> (new) — resolves the carried block as an <code>ItemStack</code> via <code>ItemModelResolver.updateForTopItem(..., ItemDisplayContext.NONE, ...)</code> and submits it through the transform above, shared by both first- and third-person call sites.</li>
<li><code>ClientEvents</code> — added a <code>RenderHandEvent</code> listener that cancels vanilla hand rendering and draws the carried block instead, on the main-hand pass only.</li>
<li><code>CarryingItemRenderLayer</code> — now delegates straight to <code>CarriedObjectRender.draw(...)</code> instead of anchoring to the hand bone via <code>translateToHand</code>.</li>
<li><code>ICarryOnRenderState</code> / <code>PlayerRenderStateMixin</code> / <code>AvatarExtractorMixin</code> — the render state now also caches a reference to the <code>Player</code> entity being rendered, needed by the shared draw call.</li>
<li>Removed <code>ItemInHandRendererMixin</code> and <code>CarriedBlockRenderer</code> (superseded by the event-based approach above).</li>
</ul>
